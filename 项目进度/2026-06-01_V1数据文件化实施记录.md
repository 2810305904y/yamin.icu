## 本次目标

在 V0 视觉原型基础上，先做 V1 的数据文件化基础。

目的不是马上做后台，而是先让这些内容从页面里拆出来：

- 项目区卡片。
- 正在进行 / 待办。
- 奇怪念头。
- 自媒体与视频账号。

这样后续做 `/admin` 编辑页时，可以围绕同一份内容结构继续做。

## 内容编辑方式

当前先通过数据文件维护内容：

```txt
v1/content/site-data.mjs
```

里面分为：

```txt
identity   站点签名
projects   项目区
todos      待办区
thoughts   奇怪念头区
channels   自媒体区
```

每条内容都有 `order` 和 `visible`，为后续排序、隐藏、后台编辑做准备。

## 后台方向

后续 `/admin` 可以复用这些结构：

- 新增内容 -> 往对应列表里增加一条。
- 删除内容 -> 从对应列表移除，或先设为 `visible: false`。
- 排序 -> 修改 `order`。
- 隐藏 -> 修改 `visible`。
- 保存 -> 后续再决定保存到文件、数据库或接口。

后续动效需求：

- 奇怪念头区后续可以从静态标签升级为一个小型“念头空间”。
- 每一个奇怪念头是一张独立漂浮卡片，拥有自己的碰撞体积。
- 念头卡片在区域内随机缓慢运动；相互碰到时会互相弹开，形成轻量物理碰撞感。
- 每次载入主页时，从可见念头数据中随机选取一部分放入这个区域，不一定全部显示。
- 念头可以每隔 3 到 5 秒随机新增一个可见卡片，也可以每隔 3 到 5 秒随机隐藏一个卡片。
- 卡片变为不可见后，应同时移除碰撞体积，不再参与碰撞计算。
- 卡片大小、初始位置、运动方向和速度可以随机化。
- 先做成轻量前端动效，不让它影响项目区、待办区和频道区的阅读；移动端可以做降级或关闭复杂碰撞。
- V1 先保证页面结构和内容管理稳定；该效果可放入近期更新预期，等当前后台和布局稳定后再实施。
