# 版本命名规则

文档版本：V2.2
整理日期：2026-06-08

## 核心逻辑

本项目的版本号不是严格的软件语义化版本，而是为了方便协作和记录项目阶段。

从 `V1.3.10` 起，优先使用三段式命名：

```txt
V1       -> 主版本，代表当前个人主页整体形态
V1.3     -> 功能阶段，第二位数字代表一个较明确的功能更新阶段
V1.3.10  -> V1.3 阶段内的第 10 次小更新
V2       -> 大结构升级，例如 3D 项目轮
```

三段式含义：

```txt
第一位：整体主页大版本
第二位：功能阶段，每进入一组新功能或明确方向时递增
第三位：该功能阶段内的小版本序号，从 1、2、3 这样递增
```

## 当前阶段

当前阶段记为 `V1.6`。

当前基准关系：

- `V1.4` 是桌面主页视觉基准：固定 `2400 x 1200` 的 2:1 设计画布、四区地图骨架和整体等比例缩放。
- `V1.5` 是手机端竖版布局与测试服安全阶段。
- `V1.6` 是首屏加载体验阶段，在不重排主页骨架的前提下增加全屏读取层。
- 后续功能更新优先保护当前主页骨架，不默认重排卡片、字体和分割线。

## 什么时候递增第二位

只有当功能范围明显换阶段时，才递增第二位。

例如从 `V1.3.x` 进入 `V1.4.x`：

- 首页进入 3D 项目轮或新的主要交互结构。
- 反馈通道、留言区、账号系统进入正式可用状态。
- 首页信息结构有明显变化。
- 后台编辑能力进入新的大模块，例如权限、审计、批量内容管理。

## 历史命名兼容

早期项目记录中出现过 `V1.21`、`V1.22`、`V1.39` 这种两段式小版本写法。它们保留在历史文档中，不需要批量改名。

从 `V1.3.10` 往后，新文件、新缓存号、新提交说明优先采用三段式。

## 文档记录方式

- 阶段文档可以叫 `V1.4...`。
- 阶段内小更新可以叫 `V1.4.0...`、`V1.4.1...`；历史 V1.3 阶段保留 `V1.3.10...`、`V1.3.11...`、`V1.3.12...`。
- 如果某次只是很小的视觉或文案微调，也可以只记录在对应阶段文档里，不一定单独开新文件。
- `AGENTS.md` 和 `Memory.md` 只记录长期工作习惯，不记录这种项目历史。
